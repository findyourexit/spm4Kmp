# Bridge SPM Resources – Design Document

## Key Questions Answered

### 1. How is the bridge target declared? Does it emit `resources:`?

The bridge target is generated by `GenerateManifest.kt` as a standard `.target(name:, dependencies:, path:, resources:, ...)` block.

**Before this change:** `resources:` was emitted only when the convention-based auto-discovery found specific folders inside the bridge source directory:
- `Resources-process` (or `Resources`) → `.process(...)`
- `Resources-copy` → `.copy(...)`
- `Resources-embed` → `.embedInCode(...)`

This logic lives in `buildResourcesPath()` inside `generateManifest/ConfigureTask.kt`.

**There was no DSL** to declare bridge resources programmatically.

### 2. Does CopiedResourcesFactory already discover the bridge target's `.bundle`?

**Yes.** `CopiedResourcesFactory` scans `inputBuiltDirectory.listFiles { it.extension == "bundle" }` which covers all `.bundle` directories in the per-target build directory root. When SwiftPM compiles a bridge target with resources, it produces `<PackageName>_<TargetName>.bundle` (e.g. `nativeIosShared_nativeIosShared.bundle`) in that exact location. No changes to `CopiedResourcesFactory` or `CopyPackageResourcesTask` are required.

## Design Implemented

### New Public API

**`BridgeResourceRule`** — `definition/BridgeResourceRule.kt`

A `Serializable` sealed class with three variants:
```kotlin
BridgeResourceRule.Process("path")     // → .process("path")
BridgeResourceRule.Copy("path")        // → .copy("path")
BridgeResourceRule.EmbedInCode("path") // → .embedInCode("path")
```

**`PackageRootDefinitionExtension.bridgeResourceRules(vararg rules)`**

A `public` DSL function to declare resource rules for the bridge target.

### Usage in `build.gradle.kts`

```kotlin
swiftPackages {
    // ... existing configuration ...

    bridgeResourceRules(
        BridgeResourceRule.Process("Resources"),        // process a whole folder
        BridgeResourceRule.Copy("FixedLayout.json"),    // copy a single file verbatim
        BridgeResourceRule.EmbedInCode("shader.metal"), // embed bytes as Swift constant
    )
}
```

### Files Changed

| File | Change |
|------|--------|
| `definition/BridgeResourceRule.kt` | **NEW** – sealed class with Process / Copy / EmbedInCode |
| `definition/PackageRootDefinitionExtension.kt` | Added `bridgeResourceRulesList` + `bridgeResourceRules(vararg)` |
| `manifest/TemplateParameters.kt` | Added `bridgeResourceRules: List<BridgeResourceRule>` field |
| `manifest/GenerateManifest.kt` | Updated `getResourceSettings()` to merge auto-discovered paths with extra rules |
| `tasks/apple/generateManifest/GenerateManifestTask.kt` | Added `bridgeResourceRules: ListProperty<BridgeResourceRule>` task input |
| `tasks/apple/generateManifest/ConfigureTask.kt` | Wires `swiftPackageEntry.bridgeResourceRulesList` → task input |

### How Resource Rules Flow

```
build.gradle.kts
  └─ bridgeResourceRules(...)
       └─> PackageRootDefinitionExtension.bridgeResourceRulesList
             └─> ConfigureTask.kt (set on GenerateManifestTask)
                   └─> GenerateManifestTask.bridgeResourceRules ListProperty
                         └─> TemplateParameters.bridgeResourceRules
                               └─> getResourceSettings() in GenerateManifest.kt
                                     └─> emitted into Package.swift resources: [...]
                                           └─> SwiftPM builds → <Pkg>_<Target>.bundle
                                                 └─> CopiedResourcesFactory discovers bundle ✓
```

## Assumptions

1. **Path is relative to the bridge `Sources/` directory.** SwiftPM resolves resource paths relative to the target's source root. Users must pass paths that are valid from that perspective.
2. **Auto-discovery still works.** Convention folders (`Resources-process` etc.) continue to be detected automatically; DSL rules are additive.
3. **No de-duplication.** If a user accidentally declares a resource path already covered by auto-discovery (e.g. adds `.process("Resources")` when `Resources-process/` also exists), both entries will appear in `Package.swift`. SwiftPM will emit a warning or error. Users should use one mechanism or the other for a given path.
4. **Bundle discovery works as-is.** `CopiedResourcesFactory` scans the build directory root for `.bundle` extensions; the bridge target's bundle will be found without additional changes.

## How to Verify on a Mac with Xcode

### Prerequisites
- Xcode installed
- A KMP project using spm4Kmp with a bridge target
- Place some resources inside `src/swift/<bridgeName>/Resources/` (or another sub-folder)

### Steps

1. **Declare resources in `build.gradle.kts`:**
   ```kotlin
   swiftPackages {
       bridgeResourceRules(
           BridgeResourceRule.Process("Resources"),
       )
   }
   ```

2. **Run manifest generation:**
   ```bash
   ./gradlew generateSwiftPackageManifest
   ```
   Check the generated `build/spmKmpPlugin/<name>/Package.swift` — the bridge target should contain:
   ```swift
   resources: [.process("Resources")]
   ```

3. **Build the Swift package:**
   ```bash
   ./gradlew compileSwiftPackage
   ```
   After build, inspect the scratch directory:
   ```bash
   find build/spmKmpPlugin/<name>/scratch -name "*.bundle" -maxdepth 6
   ```
   You should see `<PackageName>_<TargetName>.bundle`.

4. **Run from Xcode:** Build and run the iOS app. Inspect the `.app` bundle:
   ```bash
   find ~/Library/Developer/Xcode/DerivedData -name "<PackageName>_<TargetName>.bundle" 2>/dev/null
   ```
   The bundle should be present inside the `.app` package, confirming `CopyPackageResourcesTask` successfully discovered and copied it.

5. **Access resources from Swift code:**
   ```swift
   // Bundle.module is auto-generated by SwiftPM for targets with resources
   let image = UIImage(named: "MyImage", in: Bundle.module, compatibleWith: nil)
   ```

### What to Look For
- ✅ `resources:` array present in generated `Package.swift` with declared paths
- ✅ `.bundle` file present in SPM scratch directory after compile
- ✅ `.bundle` file copied into `.app` bundle by `CopyPackageResourcesTask`
- ✅ `Bundle.module` accessor available in bridge Swift code

### Unverified (Xcode Required)
- Runtime behavior of `Bundle.module` inside the bridge target
- Correct handling of asset catalogs (`.xcassets`) via `.process()`
- Behavior when a path doesn't exist (SwiftPM may warn or error)
- Interaction with code-signing of the bundle
